當初買這個路由的原因就是想刷機，不能刷機的路由器壓根不想買，剛剛看了下，已經一年多了，早過了質保，所以刷機勢在必然。

當前版本：`MiWiFi 穩定版 1.0.67`

## 前置掃盲

- SSH 是一種加密的網絡協議，用於安全地訪問和控制遠程計算機或設備；
- Telnet 是一種較舊的網絡協議，用於遠程登錄到服務器，但安全性低，通常不推薦使用。
- Linux dd 命令用於讀取、轉換並輸出數據。 dd 可從標準輸入或文件中讀取數據，根據指定的格式來轉換數據，再輸出到文件、設備或標準輸出。

永久化 SSH 需要配置創建如下目錄

```shell
mkdir /data/auto_ssh && cd /data/auto_ssh

```


並貼上如下腳本

```shell
#!/bin/sh
auto_ssh_dir="/data/auto_ssh"
host_key="/etc/dropbear/dropbear_rsa_host_key"
host_key_bk="${auto_ssh_dir}/dropbear_rsa_host_key"

unlock() {
    # Restore the host key.
    [ -f $host_key_bk ] && ln -sf $host_key_bk $host_key

    # Enable telnet, ssh, uart and boot_wait.
    [ "$(nvram get telnet_en)" = 0 ] && nvram set telnet_en=1 && nvram commit
    [ "$(nvram get ssh_en)" = 0 ] && nvram set ssh_en=1 && nvram commit
    [ "$(nvram get uart_en)" = 0 ] && nvram set uart_en=1 && nvram commit
    [ "$(nvram get boot_wait)" = "off" ]  && nvram set boot_wait=on && nvram commit

    [ "`uci -c /usr/share/xiaoqiang get xiaoqiang_version.version.CHANNEL`" != 'stable' ] && {
        uci -c /usr/share/xiaoqiang set xiaoqiang_version.version.CHANNEL='stable'
        uci -c /usr/share/xiaoqiang commit xiaoqiang_version.version 2>/dev/null
    }

    channel=`/sbin/uci get /usr/share/xiaoqiang/xiaoqiang_version.version.CHANNEL`
    if [ "$channel" = "release" ]; then
        sed -i 's/channel=.*/channel="debug"/g' /etc/init.d/dropbear
    fi

    if [ -z "$(pidof dropbear)" -o -z "$(netstat -ntul | grep :22)" ]; then
        /etc/init.d/dropbear restart 2>/dev/null
        /etc/init.d/dropbear enable
    fi
}

install() {
    # unlock SSH.
    unlock

    # host key is empty, restart dropbear to generate the host key.
    [ -s $host_key ] || /etc/init.d/dropbear restart 2>/dev/null

    # Backup the host key.
    if [ ! -s $host_key_bk ]; then
        i=0
        while [ $i -le 30 ]
        do
            if [ -s $host_key ]; then
                cp -f $host_key $host_key_bk 2>/dev/null
                break
            fi
            let i++
            sleep 1s
        done
    fi

    # Add script to system autostart
    uci set firewall.auto_ssh=include
    uci set firewall.auto_ssh.type='script'
    uci set firewall.auto_ssh.path="${auto_ssh_dir}/auto_ssh.sh"
    uci set firewall.auto_ssh.enabled='1'
    uci commit firewall
    echo -e "\033[32m SSH unlock complete. \033[0m"
}

uninstall() {
    # Remove scripts from system autostart
    uci delete firewall.auto_ssh
    uci commit firewall
    echo -e "\033[33m SSH unlock has been removed. \033[0m"
}

main() {
    [ -z "$1" ] && unlock && return
    case "$1" in
    install)
        install
        ;;
    uninstall)
        uninstall
        ;;
    *)
        echo -e "\033[31m Unknown parameter: $1 \033[0m"
        return 1
        ;;
    esac
}

main "$@"
```

之後就可以用 SSH 連接路由器了，但是會報錯：

```shell
~> ssh -p 22 root@192.168.31.1
Unable to negotiate with 192.168.31.1 port 22: no matching host key type found. Their offer: ssh-rsa
```

因爲路由器 **只支持 RSA-SHA1 host key**。然後 SSH 覺得這個算法太舊了，不接受，SSH 有兩種 RSA：`ssh-rsa` (SHA1) 和 `rsa-sha2-256`/`rsa-sha2-512`，所以需要調整一下命令：

```shell
ssh -o HostKeyAlgorithms=+ssh-rsa root@192.168.31.1
```

測試沒問題，長期的方法是修改自己本地的 SSH 配置 `~/.ssh/config`，加入：

```shell
Host 192.168.31.1
    HostKeyAlgorithms +ssh-rsa
    PubkeyAcceptedAlgorithms +ssh-rsa
```

```shell
mtd erase FIP
```

接着拔掉電源，按住 Reset（注意不是 Mesh），需要用卡針，然後按 15s 以上，連接 LAN 口，打開路由器頁面 192.168.31.1 即可打開 Uboot 頁面進行刷機。mtd layout 選擇 `immortalwrt-*`，然後把準備好的固件，上傳給 Uboot，然後等待完成即可。

immortalwrt 默認賬戶、密碼是 root/password，進去改名即可。

## OpenClash

最終目的當然是這個，直接在路由器上跑 Clash。但爲什麼不選 Sing-box，因爲自己用的機場沒有提供這個格式的訂閱，並且我用的機場訂閱是閱後即焚，折騰起來比較麻煩。

首先需要下載內核，因爲路由器下載就算用加速站點一樣非常慢，所以直接下載 https://github.com/MetaCubeX/mihomo/releases 最新內核 (`mihomo-linux-arm64-v1.19.21`)，解壓上傳至 `/etc/openclash/core/clash` 並重命名爲 `clash_meta`。因爲下載的是最新內核，所以啓用 OpenClash 依然有問題，正常啓動會報內核錯誤：

```shell
2026-03-14 00:00:36 level=fatal msg="Parse config error: path is not subpath of home directory or SAFE_PATHS: /usr/share/openclash/ui \n allowed paths: [/etc/openclash]"
2026-03-14 00:00:36 level=info msg="Start initial config
```

Dashboard 的路徑不在 `/usr/share/openclash/ui` 內核所在的路徑 `etc/openclash`，內核認爲不安全，所以拒絕運行，目前沒有特別好的辦法，因爲無法關閉 Dashboard，並且顯式聲明的配置會被覆蓋，只能進入如下操作：

```shell
ln -s /usr/share/openclash/ui/ /etc/openclash/
```

在覆寫設置 - 開發者選項中加入 [^ruby-edit]

[^ruby-edit]: https://github.com/vernesong/OpenClash/issues/4461

```shell
ruby_edit "$CONFIG_FILE" "['external-ui']" "\"/etc/openclash/ui\""
```

另一個修改建議是： https://github.com/vernesong/OpenClash/pull/4478/changes, 不過我沒有嘗試。接下來就可以正常的上網衝浪了，並且保留了原來的網段、WI-FI 以及 IP。
